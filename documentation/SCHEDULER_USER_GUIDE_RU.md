# Планировщик заданий NovaCart

## Как пользоваться

**Планировщик заданий** в админке объединяет Scheduler (периодические задания), Queue (очередь фоновых задач) и Jobs Monitor (историю запусков). Он сам по себе не работает в фоне: нужен системный запуск `cli.php jobs:run`.

При установленной задаче Windows «NovaCart Jobs» используется команда:

```text
php cli.php jobs:run --source=scheduled
```

Она запускается раз в минуту и проверяет, наступило ли время заданий Scheduler и есть ли доступные задания Queue. **Не создавайте вторую периодическую HTTPS-задачу**, если этот CLI-вызов уже работает. В мониторинге `ok (0/0)` значит, что обработка прошла без ошибок, но выполнять было нечего.

### Scheduler

В разделе Scheduler создают запись с уникальным кодом, маршрутом существующего catalog-контроллера вида `cron/...`, интервалом в секундах (не менее 60), JSON-параметрами (обычно `{}`) и статусом. Отключённую запись можно выполнить вручную кнопкой запуска. Кнопки изменения, включения/выключения и удаления управляют только выбранным заданием.

**Важно:** маршрут должен существовать. Планировщик не создаёт обработчик PHP автоматически. Не запускайте незнакомые обработчики: они могут менять данные магазина.

### Queue

Очередь показывает статусы `pending` (ожидает), `processing` (обрабатывается), `done` (выполнено), `failed` (ошибка). Доступны поиск, фильтры, сортировка, запуск, повтор неудачного задания и удаление. Прежде чем повторять `failed`, проверьте «Последняя ошибка». Очистка удаляет только завершённые задания старше семи дней, после подтверждения.

### Jobs Monitor

`ok` — успешно; `warning` и `error` требуют проверки деталей. Источники: `CLI (по расписанию)` при параметре `--source=scheduled`, `CLI (вручную/без метки)` без него, `HTTPS Web Cron` при защищённом HTTP-вызове. Старые записи могут иметь неизвестный источник.

## Пример: ежедневное обновление курсов валют

В NovaCart уже есть обработчик **`cron/currency`** (`upload/catalog/controller/cron/currency.php`); дополнительный PHP-файл создавать не нужно. Он обращается к выбранному провайдеру валют и **может изменять значения в таблице валют**, поэтому сначала проверяйте его в локальной тестовой базе.

### Предварительные условия

1. В настройках магазина включена автоматическая актуализация валют (`config_currency_auto`).
2. В `config_currency_engine` выбран существующий провайдер, например `nbu` или `ecb`; соответствующее расширение валют включено (`currency_nbu_status` или `currency_ecb_status`).
3. Для NBU/ECB PHP должен иметь cURL и доступ к соответствующему внешнему API; провайдеры используют также JSON или DOM/XML. Проверьте, что базовая валюта магазина присутствует в данных выбранного провайдера.
4. Сохраните исходные значения валют до запуска (например, в админке **Локализация → Валюты** или резервной копии тестовой БД). Ручной запуск действительно обновляет курсы; режима dry-run у обработчика нет.

Если автоматическое обновление выключено либо провайдер не выбран/отключён, обработчик завершает работу без обновления значений и пишет об этом в «Сообщении». Это **не подтверждает успешное получение курсов**.

### Добавление задания

Откройте страницу **Планировщик заданий**, заполните:

| Поле | Значение |
| --- | --- |
| Код | `currency.daily` |
| Маршрут | `cron/currency` |
| Интервал (секунды) | `86400` (сутки) |
| Параметры JSON | `{}` |
| Статус | **Отключено** для первого теста |

Сохраните. Нажмите **«Запустить сейчас»** только на локальном окружении с тестовыми данными и проверенными настройками провайдера. Затем убедитесь, что:
- в строке задания указан результат `success` и информативное сообщение;
- значения валют и дата изменения соответствуют ответу провайдера (сравните с сохранёнными до запуска);
- в журнале ошибок нет ошибок получения или разбора курсов.

Если результат `error`, сначала исправьте причину. Не включайте автоматизацию при ошибке.

После успешной локальной проверки включите задание. Достаточно уже работающего системного `jobs:run`. Следующее выполнение определяется колонкой «Следующий запуск». Не добавляйте то же обновление в Windows Task Scheduler отдельно.

### Замечания по провайдерам

- `nbu` использует API Национального банка Украины, базой ответа является UAH.
- `ecb` использует XML-данные Европейского центрального банка, базой ответа является EUR.
- Провайдеры `nbu` и `ecb` возвращают из `refresh()` массив `success/message`. Scheduler должен учитывать `success=false`, а не интерпретировать сам массив как успех. Это проверяется реализацией `cron/currency`.
- Указанные провайдеры используют отключённую проверку TLS-сертификата. До применения на публичном сервере это следует отдельно исправить и проверить доверенные сертификаты. Не считайте такой транспорт безопасной настройкой по умолчанию.

## При неполадках

- `jobs:run` сообщает `ok`, но Scheduler `0/0`: нет наступивших к выполнению заданий.
- Ручной запуск `cron/currency` отвечает «automatic refresh is disabled» или «provider is not configured»: исправьте настройки валют.
- Курсы не обновились и `error`: проверьте доступность API, выбранный провайдер, базовую валюту и последнюю ошибку задания.
- Jobs Monitor перестал обновляться: проверьте задачу «NovaCart Jobs» в Windows, рабочий каталог и аргументы.
