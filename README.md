# NovaCart

**NovaCart** — развиваемая платформа интернет-магазина на базе архитектуры **OpenCart 3.0.3.9**.

Проект сохраняет привычную структуру OpenCart 3.x и совместимый подход к контроллерам, моделям, шаблонам, расширениям и OCMOD, одновременно развивая административную часть, инструменты разработчика, кеширование, установщик и базовые возможности системы.

Текущая версия ядра:

```text
NovaCart 3.0.3.9
```

В составе проекта предусмотрены три основные локализации:

* 🇺🇦 Украинская — `uk-ua`
* 🇷🇺 Русская — `ru-ru`
* 🇬🇧 Английская — `en-gb`

---

## Основные возможности

### Улучшенная административная панель

Административная часть NovaCart развивается отдельно от стандартного интерфейса OpenCart 3.x.

Среди реализованных изменений:

* улучшенная навигация административной панели;
* расширенное многоуровневое меню;
* дополнительные инструменты управления каталогом;
* быстрые действия для создания товаров, категорий, производителей и других сущностей;
* управление режимом обслуживания из шапки административной панели;
* доработанные элементы интерфейса;
* расширенные инструменты разработчика и обслуживания магазина.

---

## Каталог

NovaCart содержит стандартные средства управления каталогом OpenCart и дополнительные инструменты.

Доступно управление:

* категориями;
* товарами;
* производителями;
* атрибутами;
* группами атрибутов;
* опциями;
* фильтрами;
* загрузками;
* отзывами;
* информационными страницами;
* периодическими платежами.

### Массовое добавление атрибутов

В административной панели реализован отдельный инструмент массового создания атрибутов.

Он позволяет:

* создавать сразу несколько атрибутов;
* работать с несколькими языками;
* использовать административный язык как основной;
* автоматически подставлять основной текст при отсутствии перевода;
* выбирать группу атрибутов;
* проверять существующие атрибуты;
* пропускать дубликаты;
* получать отчёт о добавленных и пропущенных значениях.

Это значительно упрощает первоначальное заполнение больших каталогов.

## Встроенный блог

NovaCart содержит собственную систему блога, интегрированную непосредственно в административную панель.

Поддерживается управление:

* статьями;
* категориями статей;
* отзывами;
* настройками блога.

Для базовой работы с публикациями установка отдельного модуля блога не требуется.

## Кеширование

Кроме стандартного файлового кеша в NovaCart присутствует собственный файловый кеш **FastFile**.

### FastFile

Основные особенности:

* распределение кеш-файлов по подкаталогам;
* хранение массивов в JSON;
* хранение остальных значений в текстовом формате;
* TTL записывается через время модификации файла;
* атомарная запись через временный файл и `rename()`;
* удаление повреждённых JSON-записей;
* автоматическое удаление просроченных записей;
* очистка кеша через административную панель.

Распределение файлов по каталогам позволяет избежать накопления большого количества кеш-файлов в одной директории.

## Инструменты разработчика

В административной панели NovaCart предусмотрен расширенный раздел для разработчика.

Он отображает информацию о:

* версии PHP;
* версии Twig;
* состоянии OPcache;
* наличии ionCube Loader;
* основных параметрах PHP.

Контролируются, в частности:

```text
max_input_vars
session.gc_maxlifetime
session.cookie_lifetime
memory_limit
max_execution_time
upload_max_filesize
post_max_size
```

Также из административной панели можно отдельно очищать:

* системный кеш;
* кеш изображений;
* кеш шаблонов;
* SASS-кеш;
* все типы кеша одновременно.

Для операций очистки отображается фактическое количество удалённых файлов и освобождённое дисковое пространство.

## Безопасность

NovaCart сохраняет механизм OpenCart для переноса каталога `storage` за пределы публичной директории сайта.

Это позволяет вынести из web-root:

```text
cache/
download/
logs/
modification/
session/
upload/
```

После переноса пути в конфигурационных файлах обновляются автоматически.

### Аварийная очистка модификаторов

В проект также добавлен механизм аварийной очистки кеша модификаций.

Он предназначен для ситуаций, когда ошибка в OCMOD или модифицированном файле делает административную панель недоступной.

Доступ защищён:

* случайным токеном;
* SHA-256 хешем токена;
* ограниченным сроком действия;
* одноразовым использованием.

После выполнения операции токен удаляется.

## Режим обслуживания

Состоянием режима обслуживания магазина можно управлять непосредственно из административной панели.

Это позволяет быстро:

* закрыть витрину для посетителей;
* выполнить технические работы;
* вернуть магазин в рабочий режим,

без перехода в общие настройки магазина.

## Установщик

NovaCart содержит доработанный web-установщик.

Установщик:

* проверяет версию PHP;
* проверяет необходимые PHP-расширения;
* проверяет права доступа к каталогам;
* создаёт `config.php`;
* создаёт `admin/config.php`;
* настраивает подключение к базе данных;
* позволяет выбирать SQL-дамп;
* содержит механизм проверки/восстановления схемы базы данных.

Если конфигурационный файл отсутствует, при открытии магазина автоматически запускается установщик.

## Системные требования

### PHP

Минимальная версия:

```text
PHP 7.3.0
```

Рекомендуется использовать актуальную совместимую версию PHP после проверки используемых расширений и модулей.

### PHP-расширения

Установщик проверяет наличие:

```text
GD
cURL
OpenSSL
zlib
ZIP
DOM
Hash
XMLWriter
JSON
```

Также требуется как минимум одно из:

```text
iconv
mbstring
```

### База данных

В проекте присутствуют драйверы:

```text
MySQLi
PDO
PostgreSQL
```

Для стандартной конфигурации OpenCart/NovaCart наиболее типичным вариантом является MySQL или MariaDB через `mysqli`.

### PHP configuration

Должно быть включено:

```ini
file_uploads = On
```

Автоматический запуск PHP-сессии должен быть отключён:

```ini
session.auto_start = Off
```

## Установка

### 1. Скачать NovaCart

Клонируйте репозиторий:

```bash
git clone https://github.com/bernson-dev/novacart.git
```

или скачайте архив репозитория через GitHub.

### 2. Скопировать файлы

Содержимое:

```text
upload/
```

необходимо разместить в корневом каталоге сайта.

Например:

```text
public_html/
├── admin/
├── catalog/
├── image/
├── install/
├── system/
├── index.php
└── ...
```

Не нужно копировать сам каталог `upload` как дополнительный уровень, если корнем сайта должен быть непосредственно NovaCart.

### 3. Создать базу данных

Создайте пустую базу данных и пользователя с необходимыми правами.

### 4. Запустить установщик

Откройте домен магазина в браузере:

```text
https://example.com/
```

При отсутствии `config.php` NovaCart автоматически перенаправит браузер в установщик.

### 5. Выполнить установку

Укажите:

* драйвер базы данных;
* сервер базы данных;
* имя базы;
* пользователя;
* пароль;
* префикс таблиц;
* данные администратора.

После проверки окружения установщик создаст конфигурацию магазина.

### 6. Удалить каталог установки

После успешной установки каталог:

```text
install/
```

не должен оставаться публично доступным.

## Расширения

NovaCart сохраняет архитектуру расширений OpenCart 3.x.

Структура административного раздела предусматривает расширения типов:

```text
analytics
captcha
currency
dashboard
feed
fraud
module
payment
report
shipping
theme
total
```

Поддерживается стандартный для OpenCart 3.x механизм модификаций **OCMOD**.

> Совместимость конкретного стороннего расширения необходимо проверять отдельно, поскольку NovaCart содержит изменения ядра и административного интерфейса.

---

## Совместимость с OpenCart

NovaCart основан на архитектуре ветки OpenCart 3.x и сохраняет её основные принципы:

```text
Controller
Model
View
Language
Event
Modification / OCMOD
Extension
```

При этом NovaCart не следует рассматривать как полностью неизменённый OpenCart.

В проекте модифицируются:

* административная панель;
* системные библиотеки;
* кеширование;
* установщик;
* каталог;
* работа с модификациями;
* вспомогательные инструменты разработчика.

Поэтому перед установкой стороннего модуля рекомендуется проверить изменения, которые он вносит в ядро.

---

## Для разработчиков

Основная разработка ведётся непосредственно в:

```text
upload/
```

При изменении контроллеров, моделей или шаблонов необходимо учитывать кеш:

```text
system/storage/cache/
system/storage/modification/
```

После изменений OCMOD рекомендуется обновить кеш модификаций.

После изменений шаблонов при необходимости очистите template cache через панель разработчика.
